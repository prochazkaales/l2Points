# Část 3 – Můj týden: implementační plán

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Hráč na úvodní stránce `/` vidí mřížku bossů × dny vybraného týdne. Svou účast zaškrtává s okamžitým uložením a nahoře vidí body a % za týden. Úpravy hlídá server: jen vlastní účast, okno dnes −6, od začátku evidence, jen platné sloty.

**Architecture:**
- Čistá logika patří do `L2Points.Domain`:
  - pravidla úprav,
  - sestavení mřížky,
  - souhrn hráče,
  - parsování týdne.
- Aplikační služby, které sahají do DB, patří do `L2Points.Infrastructure/Services` přes `IDbContextFactory`, aby šly testovat na SQLite. `PlayerStatsService` je sdílená služba, kterou rozšíří část 4.
- UI tvoří znovupoužitelné komponenty v `L2Points.Web/Components/Attendance`. Mřížku převezme detail hráče (část 4) i admin oprava účasti (část 6).

**Tech Stack:** .NET 10, Blazor Interactive Server, MudBlazor 9.x, EF Core 10, xUnit, `FakeTimeProvider`.

**Spec:** `docs/superpowers/specs/2026-10-28-l2points-design.md` (§3.2–3.5, §4 bod 2) · Roadmapa s poznámkami z review: `docs/superpowers/plans/2026-10-28-00-roadmap.md` · Konvence: `CLAUDE.md`

## Global Constraints

- UI česky, kód, komentáře a commity anglicky. Commit končí prázdným řádkem + `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- „Dnes“ = `AppTime.TodayInPrague(TimeProvider)`. Časy chaotic se zobrazují v Prague čase přes `AppTime.ToPragueTime(date, timeUtc)` ve formátu `HH:mm`.
- Pravidla úprav, vždy kontrolovaná na serveru:
  - hráč: `max(trackingStart, today − 6) ≤ date ≤ today`, jen vlastní účast,
  - admin: `trackingStart ≤ date ≤ today`, komukoli.
  - Přidání vyžaduje existující a aktivní aktivitu a `ScheduleCalculator.IsValidSlot`. Odebrání platnost slotu nevyžaduje.
- DB přístup jen přes `IDbContextFactory<AppDbContext>` (kontext na operaci). Žádný `AppDbContext` v komponentě.
- Týden v URL: `/?week=yyyy-MM-dd`. Libovolné datum se normalizuje na pondělí. Neplatná nebo chybějící hodnota znamená aktuální týden.
- Kategorie v souhrnu (pořadí a popisky): **Celkem**, **Normal**, **Večerní**, **Ranní**, **CS**. Procento se zobrazuje celé číslo + „ %“. `null` se zobrazí jako „–“.
- Mobil: mřížka se na úzkém displeji vodorovně posouvá, první sloupec (boss) zůstává přilepený. Dark i light mód.

## Rozhodnutí tohoto plánu

- **Aplikační služby v Infrastructure** (`Services/`), ne ve Web. Potřebují DB a testy běží v `Infrastructure.Tests`. Web jen volá služby. Zapsat do CLAUDE.md.
- **Admin pravidla už teď** (`isAdmin` parametr). Část 6 je jen napojí, část 3 volá s `actor == target`.
- **Osiřelá účast** (aktivita deaktivovaná nebo slot už není v rozpisu) se v mřížce zobrazí jako zaškrtnutá buňka mimo rozpis. Jde odškrtnout, pokud je den v okně.

## Review Focus

1. **Dvojklik / dvě záložky** přidají stejnou účast dvakrát. Druhé přidání musí skončit `Ok`, ne chybou (unikátní index → idempotence) → test v Task 3.
2. **Podvržený požadavek** (cizí `targetUserId`, datum mimo okno, neplatný slot, neznámá aktivita) server odmítne s odpovídajícím výsledkem a nic nezapíše → testy v Task 3.
3. **Nesmysl v URL** (`?week=abc`, `?week=2026-10-29`) → aktuální týden, nebo pondělí 26. 10., bez pádu → test v Task 1.
4. **Hranice půlnoci**: v 23:30 UTC 28. 10. je v Praze už 29. 10., takže 29. 10. jde upravit a 22. 10. už ne → test v Task 3.
5. **Deaktivovaná aktivita s historií** je v mřížce vidět, jde odškrtnout a dál dává body → testy v Task 2 a Task 3.
