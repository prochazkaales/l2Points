# Část 2 – Doména a rozpis: implementační plán

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Čistá, otestovaná doménová logika L2Points: aktivity a rozpis, týdny v českém čase, okno úprav, výpočet bodů a % účasti. K tomu persistence (entity, migrace, seed výchozího katalogu) připravená pro části 3–6.

**Architecture:** `L2Points.Domain` obsahuje POCO entity, enumy a statické kalkulačky bez závislostí (žádné EF, žádné ASP.NET). Infrastructure entity mapuje přes `IEntityTypeConfiguration`, seeduje výchozí katalog za běhu (idempotentně, nepřepisuje úpravy admina) a nabízí načítání katalogu a nastavení. UI se v této části nemění.

**Tech Stack:** .NET 10, EF Core 10 (SQL Server, SQLite v testech), xUnit, `Microsoft.Extensions.TimeProvider.Testing` (`FakeTimeProvider`).

**Spec:** `docs/superpowers/specs/2026-10-28-l2points-design.md` (hlavně §3) · Roadmapa: `docs/superpowers/plans/2026-10-28-00-roadmap.md` · Konvence: `CLAUDE.md`

## Global Constraints

- Domain nemá žádné package ani project reference. Nesmí znát `AppUser`. Uživatele reprezentuje `string UserId` a hodnoty `ActiveFrom` / `DeactivatedAt` předané parametrem.
- Data jsou `DateOnly` v kalendáři **Europe/Prague**. Časy rozpisu jsou `TimeOnly` v **UTC**. Všechny `DateTime` v DB jsou UTC a čtou se zpět s `DateTimeKind.Utc`.
- Týden = pondělí–neděle (Prague).
- „Dnes“ se získává jen přes `TimeProvider` (`AppTime.TodayInPrague`).
- Výchozí katalog, verbatim ze spec §3.1:
  - **Normal Flexible** (očekávaný počet / týden): QueenAnt 6, Core 4, Orfen 4, Zaken 4, Frintezza 3
  - **Baium:** Weekly, sobota, 20:00 UTC
  - **Antharas:** Biweekly, neděle, kotva **2026-11-01**
  - **Valakas:** Biweekly, neděle, kotva **2026-11-08**
  - **Chaotic** (Evening / Morning UTC):
    - QueenAnt Po–Pá 18:00 / 01:30
    - Core Po–Pá 18:30 / 02:00
    - Orfen Po–Pá 19:00 / 02:30
    - Zaken Po, St, Pá 19:30 / 03:00
    - Frintezza Út, Čt 19:30 / 03:00
  - **CastleSiege:** Weekly, neděle, 18:00 UTC
  - **Body:** výchozí 1 za vše
- Nastavení `TrackingStartDate` = **2026-10-26**.
- Kategorie %: **Normal** (vše NormalEpic), **Evening** (Chaotic Večerní), **Morning** (Chaotic Ranní), **CastleSiege**, plus Celkem.
- % = Σ min(účasti, očekávané) ÷ Σ očekávané, po týdnech a „bucketech“ (aktivita × slot). Bez vážení body. Body = součet bez stropu.
- Rozpracovaný týden / částečný rozsah: fixní výskyty s datem v rozsahu; flexibilní = `ceil(ExpectedPerWeek × dnyVRozsahu / 7)`.
- Okno úprav hráče: `today − 6 ≤ date ≤ today`.
- Kód, komentáře a commity anglicky. Commit končí prázdným řádkem + `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Rozhodnutí tohoto plánu (odchylky od orientačního modelu ve spec §5.2)

- **Sloty jako enum, ne tabulka.** `EventSlot { None = 0, Evening = 1, Morning = 2 }`. Sloty jsou pevně dva a mají vlastní sloupce v přehledu. `None` místo `null` drží unikátní index účasti stejný na SQL Serveru i SQLite.
- **Neaktivní aktivita** nemá očekávané výskyty a nedá se nově zaškrtnout. Body ze starých účastí zůstávají, do % se nepočítají.
- **Body** se počítají ze všech předaných účastí (volající filtruje období, typicky od `TrackingStartDate` do dneška), nezávisle na `ActiveFrom` / `DeactivatedAt`. Procenta se počítají jen v období hráče.
- **Seed za běhu** (`ReferenceDataSeeder`), ne `HasData`. Vloží jen chybějící aktivity (podle `Code`) a nastavení, existující nikdy nepřepíše.
