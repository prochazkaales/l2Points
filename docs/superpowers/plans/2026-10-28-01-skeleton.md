# Část 1 – Kostra aplikace: implementační plán

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Spustitelná kostra L2Points. Admin se přihlásí, vidí moderní MudBlazor layout s dark/light přepínačem a placeholder stránkami. Aplikace jde postavit do Docker image.

**Architecture:** Jedna Blazor Web App (.NET 10, globálně Interactive Server). Účtové stránky (login, změna hesla) jsou statické SSR, protože nastavují cookie. ASP.NET Core Identity + EF Core (SQL Server) v projektu Infrastructure. Doménový projekt je zatím prázdný a naplní ho část 2.

**Tech Stack:** .NET 10, Blazor, MudBlazor, ASP.NET Core Identity, EF Core 10 SQL Server, xUnit, SQLite in-memory (testy), Docker.

**Spec:** `docs/superpowers/specs/2026-10-28-l2points-design.md` · Roadmapa: `docs/superpowers/plans/2026-10-28-00-roadmap.md`

## Global Constraints

- `TargetFramework` `net10.0`, `Nullable` `enable`, `ImplicitUsings` `enable` (přes `Directory.Build.props`).
- UI texty česky. Kód, komentáře, názvy a commit messages anglicky.
- Render mode: globálně `InteractiveServer`, stránky s `[ExcludeFromInteractiveRouting]` jsou statické SSR.
- Konfigurace: `ConnectionStrings:Default`, `Admin:UserName`, `Admin:Password`, `Admin:Nick` (v env `Admin__UserName` atd.).
- Role: `Admin`, `Player`. Admin má vždy obě role.
- Kontejner poslouchá na portu `8080`, health endpoint `/health` (anonymní).
- Volba tématu v `localStorage` pod klíčem `l2p-theme` (`"dark"` / `"light"`), výchozí podle systému.
- Lokální DB: `(localdb)\MSSQLLocalDB`, databáze `L2Points`. Docker lokálně není nainstalovaný.

## Review Focus

1. **Deaktivovaný účet** (`IsActive = false`) se nesmí přihlásit. Login ukáže „Účet je deaktivován.“ → test v Task 2 (`AppSignInManagerTests`).
2. **Restart aplikace** (seed proběhne znovu) nesmí vytvořit druhého admina ani spadnout → test v Task 2 (`Seed_is_idempotent`).
3. **Chybějící admin config** při prázdné DB → start musí selhat s jasnou chybou, ne tiše běžet bez admina → test v Task 2.
4. **Nepřihlášený uživatel** na libovolné stránce → přesměrování na `/login?returnUrl=…`, po přihlášení návrat zpět. `/health` a `/login` zůstávají anonymní → ověření v Task 3, krok 6.
5. **Změna hesla** nesmí uživatele odhlásit (security stamp se mění, cookie se musí obnovit) → stránka je proto statické SSR s `RefreshSignInAsync`, ověření v Task 3, krok 6.
